## 2. 条件1の検証: 他6ページのsafe-area確認 — **十分**

提出された証拠を鵜呑みにせず、自分でファイルを開いて確認した。

- **証拠の実在と真正性**: safe-area-{foods, food-detail, eaten, areas, stores, store-detail}-{390,430}.png の計12枚がすべて存在。解像度は1179×2556（iPhone 14 Pro ネイティブ解像度）で、Dynamic Island・status bar・時刻が実写されており、ブラウザ幅シミュレーションではなく実Simulatorのスクリーンショットであることを確認
- **拡大目視の結果**（390系6枚すべて確認）:
  - `/foods`: 見出し「フードを探す」が島の下に十分なクリアランスで表示。カテゴリチップ・検索バーも正常
  - `/foods/[id]`: 「一覧へ戻る」ボタンと図鑑コード（NDL-001）が島と非干渉
  - `/eaten`: 見出し「食べた記録」とサマリー行が島の下に正常配置
  - `/areas`: 見出し「エリアから探す」とエリアポスターが非干渉
  - `/stores`: 見出し「店舗一覧」と店舗リストが非干渉
  - `/stores/[id]`: 「店舗一覧へ戻る」ボタンと店舗写真が非干渉
- 全ページで横スクロール・文字切れの兆候なし

結論: 前回P1とした「他ページの島干渉リスク」は、**実機相当の証拠により否定された**。追加実装（layout.tsxへの共通safe-area処理）は不要。v1.3の発行も不要。

## 4. 申し送り（承認の妨げにはならない事項）

1. **未追跡ファイルのコミット**: design-review-after-v1-2.md と screenshots/safe-area-*.png がgit未追跡のまま。証跡として次回コミットに含めることを推奨
2. **640〜767px帯のsafe-area**（前回P3再掲): `.home-collection-hero` は640px以上で固定paddingになる。iPad縦向きをCapacitor対象にする場合は `max(env(safe-area-inset-top), 1.25rem)` への変更を将来検討
3. **IP除外リストの将来リスク**（前回P3再掲): PURE_IP_GROUP_NAMESに無いキャラ名グループがデータ次第で期間限定枠に入る余地。データ増加時に再点検
4. **ストア提出用スクリーンショット**: 今回のSimulatorスクリーンショットにはdev環境の表示が含まれるものがある。App Store/Google Play提出素材は必ず本番ビルドで撮り直すこと（docs/store-assets.md の運用に従う）
5. 本番ホームの「図鑑に登録された184種類」と銘板「販売中 183品」は母数の定義が異なる正常な差（図鑑全体 vs 販売中）だが、ユーザーが混乱しないか今後のフィードバックで観察したい
