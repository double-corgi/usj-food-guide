## 1. 現状レイアウトの把握（設計の前提・実コード確認済み）

- **下部ナビはフローティング固定**: `components/app-header.tsx` のナビは
  `fixed inset-x-4 bottom-[calc(env(safe-area-inset-bottom)+0.75rem)] z-50 … md:hidden`。
  画面下に浮くピル型で、モバイルのみ表示。z-50 で最前面。
- **本文はナビ分の余白を確保済み**: `app/layout.tsx` の `main` が `pb-28`（モバイル）/`md:pb-8`。
  つまり通常フロー内の要素（＝インライン広告）は、すでにナビと重ならないよう下端余白が取られている。
- **ヘッダーはデスクトップのみ** (`md:block`)、モバイルはヘッダー無し＝上部は比較的自由だが、下部はナビが占有。
- **探すページ**: `app/foods/page.tsx` は `<FoodGrid>` をそのまま返す。グリッド末尾には「もっと見る」と「リクエスト」CTA が既にある。
- **翻訳は凍結中**（`data/translations` 変更禁止）→ Phase 1 のラベル「広告」やプレースホルダー文言は**コンポーネント内ハードコード**にする（i18n 化は Phase 3 以降）。
- **デザイントークン**: `cream(#fffaf5)` / `sand(#e7dccb)` / `slate-200` 枠 / `park` / `ink` などが既存。広告枠は白〜クリーム背景＋薄いスレート枠で既存トーンに馴染ませる。

この構造から導かれる最重要点: **「通常フロー内のインライン広告」はナビと干渉しない／「固定広告」はナビと必ず干渉する。**

### 6（常時下固定）が不可な理由

下部ナビが `fixed … bottom z-50` で常時最前面に浮いている。固定広告を入れると
(a) ナビと同じ最下部レイヤを奪い合い**視覚的占有・遮蔽**、
(b) ナビ直近に広告が来て**誤タップ**多発、
(c) `pb-28` の余白計算が崩れ**本文・フッターがナビ/広告に潜る**、
(d) モバイルの貴重な下部領域を二重に消費し**安っぽい**。
→ 構造的に UX を壊すため今はやらない。

## 3. 推奨 / 非推奨

### 推奨
1. **【第一弾】探す（/foods）一覧の直下・フッター直前に 1 枠**（候補3b）。
2. （Phase 2 候補）商品詳細ページ下部・関連商品の手前（候補5）。
3. （Phase 2 候補）Home のセクション間に 1 枠（候補2、控えめに）。

### 非推奨（少なくとも当面）
- **常時下固定広告（候補6）**: 下部ナビと構造干渉。やらない。
- **食べたページ下部（候補4）**: 記録・達成体験を毀損しやすい。優先しない。
- **探す一覧の「途中」in-feed（候補3a）**: 誤タップ・安っぽさ・実装複雑。収益が必要になった段階で再検討。

## 4. 最初に実装すべき広告枠

- **場所**: `/foods` ページ、`<FoodGrid>` の**直後**（通常フロー、フッター直前）。グリッド内部の map には差し込まない＝カード誤タップを回避。
- **数**: 1 枠のみ。
- **中身**: 本番広告コードなし。**静的プレースホルダー**（「広告」ラベル＋"Ad space" 的な薄いダミー）。
- **理由**: 高トラフィックの主要画面でありながら、スクロール末尾という自然な切れ目。ナビ余白（`pb-28`）の内側に収まり干渉ゼロ。単一コンポーネントで追加/削除/差し替えが容易。

---

## 5. 広告枠の UI 方針

再利用可能な単一コンポーネント `components/ad-slot.tsx` を新設し、Phase 1 はこれを1箇所に置く。

- **コンテナ**: 通常フロー。`my-6`〜`my-8` の上下余白で本文から分離。`mx-auto w-full max-w-3xl`（本文幅に整列、横いっぱいにしない）。
- **見た目**: `rounded-2xl border border-slate-200 bg-white`（または `bg-cream`）。影は付けない/ごく薄く。装飾過多にしない。
- **高さ**: 小さめバナー想定で**固定高**（例 `h-24` 〜 `h-28`、モバイル中心）。**固定高により CLS（レイアウトシフト）を防止**。
- **「広告」表記**: 左上に小さく `text-[10px] font-bold uppercase tracking-wide text-slate-400` で「広告」（凍結中の翻訳は使わずハードコード）。
- **中身（Phase 1）**: 中央に淡色のプレースホルダーテキスト（例「広告スペース」）。クリック不可（リンク・onClick なし）→ 現時点で誤タップ・誤遷移リスクゼロ。
- **差し替え容易性**: ルート要素に `data-ad-slot="foods-bottom"` 等の識別属性を付け、将来 AdSense 等の枠（同サイズ）へ中身だけ差し替え可能に。`children` を受け取れる設計にしておくと尚良い。
- **アクセシビリティ**: `aria-label="広告"` 程度。スクリーンリーダ過剰読み上げを避ける。
- **禁止**: 外部 `<script>`・SDK・iframe・本番広告タグは入れない（Phase 3 まで）。
- **多言語**: 当面ハードコード日本語。i18n 対応は翻訳解凍後（Phase 3 以降）。

## 7. Phase 分け

- **Phase 1（今回）**: 本番コードなし。`components/ad-slot.tsx` を新設し、`/foods` 末尾に**1枠だけ**プレースホルダー配置。検証: ①下部ナビと干渉しない ②レイアウトシフトなし（固定高） ③フッター/本文がナビに潜らない ④モバイルで安っぽくない ⑤lint/typecheck/build/coverage 成功・Coverage 不変。
- **Phase 2**: Phase 1 の見え方を確認後、商品詳細下部・Home セクション間など複数画面へ展開するか判断。なお食べたページ・in-feed 途中・固定広告は引き続き慎重/不採用。
- **Phase 3**: 実広告コード（AdSense 等）の導入検討。CSP 更新・同意（consent）・i18n・サイズ最適化・収益計測を別タスクで設計し、専用 /goal とレビュー証跡を作成。

## 8. リスクと対策（要点）

- **CLS（読み込み時のガタつき）**: 固定高で予約。
- **誤タップ**: Phase 1 は非クリック。実広告化時はナビから十分離す（末尾配置を維持）＋枠内に余白。
- **安っぽさ**: 1枠限定・白/薄枠・小サイズ・「広告」表記で節度を担保。
- **収益 vs UX**: まず1枠で体感を確認し、データを見てから拡張（Phase 2）。

---

## 9. 最終回答（要点）

- **最初に置くべき広告位置**: 探す（/foods）ページ、商品一覧の直下・フッター直前（1枠）。
- **常時下固定広告を今やるべきか**: **NO**（下部ナビと構造干渉）。
- **Codex に投げてよいか**: **YES**（Phase 1・プレースホルダーのみ。`docs/codex-goal-unicole-ad-slot-placeholder-v1.md`）。
