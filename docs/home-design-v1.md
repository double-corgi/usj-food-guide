## 1. Objective

このホーム改修で達成すること: ホームを「整理された進捗ページ」から「自分のコレクションが置いてある棚」に変える。

4つの感情目標と実現手段:

**食べたくなる** — フード写真を「商品サムネ」ではなく「ごちそうの陳列」として扱う。今集められるフードを大判写真の横スワイプにし、1枚目から写真の物量と質感が目に入る状態にする。「あと◯日で終了」の限定情報を写真に添え、「今食べないと消える」緊張を作る。

**集めたくなる** — 進捗を数字ではなく「色づいていく棚」で見せる。取得済みはフルカラー＋取得スタンプ、未取得は暖色トーンダウンの実写真。未取得を隠さない（ロック・?は禁止。食欲をそそる写真こそが「欲しい」の源泉なので、未取得こそ見せる）。空きマスが埋まる視覚が「あと少し」を駆動する。

**もう一度開きたくなる** — (a) 棚は自分の記録で変化するため、食べた翌日に開くと棚が育っている。(b) 「今集められるフード」の表示順に日替わりローテーションを入れ、毎日違う出会いがある。(c) 終了間近の残り日数が日々減る。この3つの「昨日と違うホーム」で再訪理由を作る。

**ユニバに行きたくなる** — エリアポスター（現行の最良資産）を維持しつつ、「このエリアであと◯品」という行く理由に変換する。終了間近の限定品が「次の来園日を決めるトリガー」になるよう、期間情報をホーム上で可視化する。

## 2. Current Problem

現行ホーム（screenshots/home-home-polish-after-390.png で確認）の弱点を原因まで分解する。

**なぜファーストビューが弱いのか** — 開いた瞬間に見えるのは「ユニコレ（太字テキスト）→説明文2行→ 0/183 → 0%」。つまりブランド・説明・成績で1画面が終わり、コレクションの実体（フード写真）が1枚も無い。コレクションアプリの初見が「空の成績表」になっている。

**なぜ「集めたい」と思えないのか** — 集める対象が見えないから。183という数字は欲望を生まない。欲望を生むのは「美味しそうな写真」と「埋まりかけの棚」だが、現行FVにはどちらも無い。また残り183品という巨大な母数だけが提示され、達成可能な小さい単位（エリアで残り4品、限定コレクションで残り2品）が無いため、「やれそう」という感覚が立ち上がらない。

**なぜAI感が出るのか** — (a) 背景がクールグレー(#f6f8fa)＋淡い放射グラデ＋抽象円ボーダーという「どのプロダクトにも当てはまる装飾」であること。(b) 光スイープアニメが文脈なしの汎用演出であること。(c) 「説明文→数字→ゲージ→ラベル3つ」というテンプレ的情報並びであること。固有の世界観モチーフ（パーク、スタンプ、チケット、棚）が無く、置換可能なUIに見える。

**なぜ進捗がただの数字に見えるのか** — 進捗の表現が数字とバーしか無いから。0/183の「183」は獲得物の顔が見えない抽象数。進捗が「自分が食べたあのチュリトスの写真」と結びついていないため、達成が記憶や愛着に接続しない。

**なぜユニコレのロゴ・文字が弱いのか** — font-black＋微小なtext-shadow＋下線3pxという構成は「太字テキスト＋飾り線」の域を出ておらず、ブランドの「作られた感」が無い。周囲の見出しも全てfont-blackのため、ロゴと見出しの格差も無い。

**なぜフード写真の魅力が活かせていないのか** — (a) FVに写真ゼロ。(b) 「今集められるフード」は2列グリッドのサムネサイズで、写真が「一覧の部品」になっている。(c) 写真選定スコア（scoreHomeFood）は限定・価格有無等の管理的指標で、「写真として旨そうか」が考慮されない。(d) 取得済み/未取得の状態が写真の見た目に反映されず、写真とコレクション体験が切り離されている。

## 3. Data Scope Risk（商品数・データ範囲の注意点）

**183品の正体（コードから確定）**: ホームの「0/183」は `calculateCompletion()`（lib/food-utils.ts 245行）の total であり、その定義は「`listFoods()` の公開品質フィルタ（reviewStatus=approved、nameQualityScore≥60、confidenceScore≥45、hidden=false等。lib/repositories/foods.ts）を通過した商品のうち、`saleStatus === "active"` のものを canonical 単位で重複統合した数」である。

つまり183は:

- 「USJの全フード数」では **ない**
- 「データ取得済みの全商品数」でも **ない**（scripts/output/foods.generated.json の実数は294件、うち active 258件。品質フィルタとcanonical統合で183まで減る）
- 正しくは「**表示品質基準を満たした、現在販売中の登録商品数（canonical単位）**」

**不足の可能性**: 高い。crawlerは公式サイト等の限られたソースを上限付き（CRAWL_MAX_*環境変数）で巡回しており、網羅保証は無い。実際にデータ件数は変動しており（audit:canonicalは過去の200件基準が現状188件と合わず失敗中 — real-user-audit-v3.md）、294→183への減少も品質フィルタ起因で今後の承認作業により増える。パーク全体のフードは数百品規模とみられ、183を「全フード」と提示するのは事実誤認になる。

**ホームでの表現方針（本設計の決定事項）**:

- 「全183品」「全フード」「完全収録」「コンプリート図鑑」等、**データ完全性を断定する表現は全面禁止**
- 採用する語彙: 「**現在販売中の登録フード**」「**登録済みコレクション**」。母数を出す場合は「販売中 183品（登録分）」のように登録ベースであることを含意させる
- 達成率（%）は「現在販売中の登録商品に対する達成率」として扱い、ラベルは「達成率」のまま、注釈レベルで補足（既存の /eaten 最下部注釈と同じ思想）
- **総数を主役にしない**: 主役は「集めた数（コレクション数）」。総数・残数は従属表示。集めた数はデータ増減の影響を受けず、ユーザーの実績として常に正である

**データが増えても破綻しないUI**:

- 母数表示は3〜4桁を想定した可変幅（183→1,083になっても折り返さないタイポ設計）
- 進捗ゲージは相対値なので破綻しない。ただし母数が増えると達成率が下がる事象が起こり得るため、%の演出を控えめにし、コレクション数（絶対値）を感情の主役に置く
- 棚UI（後述）は「直近・代表のN枠」を表示する設計で、総数に依存しない

**Codex実装前に確認すべき質問（オーナー判断・要回答）**:

1. crawlerの収録方針は「公式掲載分の網羅」を目指すのか、「主要商品のキュレーション」か
2. 品質フィルタで非表示中の約75件（294−183−endedの一部）は今後承認されて増える見込みか
3. 「図鑑コンプ率」（全canonical母数）をホームに出す必要はあるか（本設計では非表示を提案。/eatenに残す）

## 4. Design Principle

ユニコレ独自の設計原則。名付けるなら「**ごちそうの棚（Tasting Shelf）**」— 高級なフードホールのショーケースに、自分のスタンプが増えていく感覚。

1. **数字より棚**: 進捗は「色づく実写真の棚」で見せ、数字は棚の注釈にする。管理ではなく達成感
2. **未取得は隠さず、焦がす**: 未取得品はロックや?ではなく「まだ味わっていないごちそう」として淡トーンで見せる。欲しさの源泉は写真自身
3. **取得はスタンプで刻む**: 取得済みには小さなゴールドのスタンプ痕（チェック＋取得日）。パークのスタンプラリー/パスポートの記憶に接続する。紙とインクの比喩は高級感と相性が良い
4. **ユニバ感は色×写真×期限で出す**: USJ Blue/Navy/Goldの維持、エリアポスター、そして「あと◯日」という限定の鼓動。キャラクターや装飾過多には頼らない
5. **高級感とゲーム感の両立**: ゲーム感は「変化・収集・期限」の構造で出し、見た目は静かに保つ。演出は短く・小さく・上質に（達成瞬間のみ動く）。常時動く装飾（光スイープ）は廃止
6. **ソシャゲ的な安さの禁止**: 紙吹雪・虹グラデ・レアリティ爆発・連続ポップアップは使わない
7. **SaaS/LP/管理画面にしない**: 白カードの量産禁止。セクションは余白と見出しで区切る。ヒーローバナー＋キャッチコピー＋CTAというLP構文を踏まない
8. **断定しない**: データ完全性・販売状況を断定する文言を置かない（Data Scope Risk準拠）
9. **昨日と違うホーム**: 日替わり表示順・残り日数・棚の成長という「開くたびの差分」を構造で保証する

## 5. Home Information Priority

現行順序（ブランド→説明→数字→販売中6品→エリア→店舗→25th→全商品→情報提供）をプロダクト目線で再設計する。

新しい優先順位と理由:

1. **ユニコレのブランド**（小さく、ただし作り込んだロゴタイプ）— アプリの署名。面積は最小、品質は最高
2. **コレクションの棚（=コレクション数・進捗の実体化）** — このアプリの「自分ごと」の核。数字（コレクション数/残り/達成率）は棚に従属して表示
3. **今集められるフード（食べたい感の発生源）** — 大判写真。限定・終了間近を優先し日替わりローテーション
4. **期間限定コレクション（汎用化した25th枠）** — 「小さくてコンプできそうな単位」を見せ、コンプ欲の着火点にする
5. **エリア別コレクション** — 現行ポスターカード維持。「行く理由」への変換装置
6. **最近の記録（食べた記録の3枚ストリップ）** — 記録がある人だけ表示。アルバムへの愛着導線（/eatenへ）
7. **店舗から探す / 全商品を見る** — 補助導線。テキスト行で静かに
8. **情報提供** — 最小。フッター直前

変更の要点: 「説明文」をFVから外す（タグラインのみ残す）。「数字の独立セクション」を廃止し棚に統合。25th固定を期間限定枠に汎用化。記録ストリップを新設（再訪動機）。

## 6. First View Design（最重要）

現行FVは不採用。新FVの構成（上から順）:

**(1) ブランド行** — ユニコレのロゴタイプ（7章の仕様）＋右側に余白。タグライン「食べた記録が、そのままコレクションになる。」を1行、小さく添える。説明文2行は削除（/aboutに既存）。

**(2) コレクションの棚（Shelf）** — FVの主役。実フード写真の小タイルを2段×5列（モバイル）で敷く。

- タイルの中身: 公開商品から選んだ実写真。**取得済み**はフルカラー＋右下に極小のゴールドスタンプ（チェックマークの刻印風、円形、直径16px程度）。**未取得**は暖色系のトーンダウン（彩度を下げ、わずかに暖色フィルタ。グレースケールにはしない — 食欲の温度を残す）
- タイル選定: 取得済みを先頭に最大N枚、残りは未取得から「限定優先＋写真品質（images有）＋日替わりシード」で充填。0品ユーザーでも棚は美しい未取得写真で満ち、「ここが色づいていく」が直感できる
- タイルはタップ可能（各商品詳細へ）。棚自体が探索の入口を兼ねる
- 角丸は小さめ（8〜10px）、タイル間ギャップ4〜6px。「ショーケースの整然」を出す。枠線・影は使わない

**(3) 棚の銘板（数字行）** — 棚の直下に1行:「コレクション {eaten}」を大きく（数字のみ32〜40px、Navy）、続けて「/ 販売中 {total}品（登録分）・残り {remaining}」を小さく(12〜13px, slate)。その下に高さ4pxのゲージ（Blue→Goldグラデ、既存トークン）。%は数字行の右端に小さく置く（主役にしない）。

**(4) チラ見せ** — FV下端に「今集められるフード」セクションの見出しと1枚目の写真上端が必ず見え、スクロールを誘発する（11章で高さを規定）。

禁止事項の遵守: ロック/?なし、達成カウントダウンなし、合成バナーなし、抽象グラデ背景なし、SaaSカードなし、巨大数字単独なし、ただのH1なし、アイコン・ヘッダー追加なし、英語タグ（COLLECTION等）なし。

背景: セクション背景はごく薄いウォームトーン（#fffaf5系、DESIGN.mdのBase回帰）を白との微差で敷き、「アルバムの紙」の温度を出す。放射グラデ・円形ボーダー・光スイープは全廃。

新規ユーザー（0品）の初見: 棚は全タイル淡トーンで「これから集める100個以上のごちそう」が見え、銘板は「コレクション 0 / 販売中183品（登録分）」。空の成績表ではなく「開封前のコレクションブック」として成立する。

## 7. Unicolle Logo Treatment

ただの太字テキスト禁止・アイコン追加禁止・ヘッダー追加禁止の制約下で、**文字だけで「刻印されたロゴ」** を作る。

仕様（CSSのみで実現可能な範囲で設計）:

- 書体: 現行のNoto Sans JP系 font-black を維持しつつ、字間を明示設計（tracking +0.04em程度。現行0.02emよりわずかに広げ、ロゴらしい「据わり」を出す）
- **二層刻印**: Navy(#071b3a)の本体の下に、Universal Gold(#fdbb30)を1px右下にオフセットした同文字を重ねる（影ではなく「箔の版ずれ」。エナメルピンバッジ/パークの真鍮銘板の質感）。現行の曖昧なtext-shadowはこの明示的な二層に置き換える
- **飾り罫**: 下線3px単線をやめ、ロゴ左右に細いゴールドの水平罫（高さ1px、長さ16〜24px）を文字の垂直中央に配置し「— ユニコレ —」の銘板構図にする。中央寄せ構図と相性が良く、テーマパークのサインの文法
- サイズ: モバイル28〜30px（現行32pxより一段小さく。FVの主役は棚であってロゴではない）。最小20pxまで二層が潰れないことを基準とする（1pxオフセットは20pxでも視認可。これ以下では単層Navyにフォールバック）
- 色は3色（Navy/Gold/背景）以内。グラデ文字・縁取り文字・斜体は禁止（安っぽさの主因）
- 検証観点: 390pxで折り返さない・タグラインとの行間が詰まらない・ダーク写真上には置かない（常に紙背景上）

## 8. Collection Progress Design

ラベルは「コレクション進捗」ではなく「**コレクション数**」を維持する（現行ラベル踏襲）。

- **主役は絶対値**: 「コレクション {eaten}」。集めた数はデータ範囲の不確実性に影響されない唯一の真実で、ユーザーの誇りに直結する
- **母数は従属＋非断定**: 「販売中 {total}品（登録分）」。「全」「すべて」を冠しない。totalが増えても破綻しないよう、数字部分は固定幅にしない
- **残り数**: 「残り {remaining}」は小さく添える。巨大な残数で絶望させないため、達成可能な小単位（期間限定コレクション・エリア）の「あと◯品」を10章・エリアカードに分担させる
- **達成率**: ゲージ＋右端の小さな%のみ。巨大%表示（現行の3.75rem）は廃止
- **数字を派手に、安っぽくなく**: 大きいのはコレクション数の1つだけ。書体はNavy単色、桁区切りあり、装飾なし。「大きさの独占」が品位を作る（全部大きいと安くなる）
- **進捗バー**: 高さ4px（現行3pxの仕様帯内）、Blue→Goldグラデ維持、グロー影(shadow)は削除。0%でも土台を表示（DESIGN.md準拠）
- **取得済み写真の活用**: 棚（6章）がその役割を担う。別途「取得済みカード」を重複表示しない
- **未取得の表現**: ロック/?を使わず、暖色トーンダウンの実写真（6章）。「見えているのに、まだ自分のものではない」が最も上品な渇望の作り方
- **取得瞬間の演出（控えめ）**: 「食べた」登録時、該当タイルが彩色されゴールドスタンプが押される短いアニメ（400〜600ms、1回限り、既存achievement-unlockキーフレームの転用可）。紙吹雪・効果音・モーダルは使わない。reduced-motion時は即時切替

## 9. Food Discovery Section（今集められるフード）

目的を「一覧の入口」から「**食欲の発生源**」に変える。

- **レイアウト**: モバイルは横スワイプの大判カード。カード幅は画面の約72〜78%（390pxで約280〜300px）、次カードが約20%見えて「続きがある」ことを示す。写真比率4:3、写真高さ約210px — 現行2列グリッド（写真幅約170px）の約3倍の面積で「旨そう」が成立する
- **件数**: 初期8件。「すべて見る →/foods」をレール末尾カードとして置く（最後まで送った人への自然な出口）
- **選定ロジック**: 現行scoreHomeFood（限定・価格・画像有無）をベースに、(a) 終了間近（remainingDays少）を最優先、(b) 画像があることを必須に格上げ、(c) 日替わりシード（日付ベースのシャッフル）を加え、毎日並びが変わるようにする。サーバーcache（revalidate 3600）と整合するよう日付単位のseedにする
- **カード内情報**（写真の下、3行以内）: 商品名（font-bold 15px、2行固定）/ 価格（Gold寄りNavy、太字）＋エリア名（小、slate）/ 状態チップ（「あと◯日」berry、または「限定」。最大1個。写真上には載せない — 写真を汚さない）
- **取得済みの扱い**: 取得済み商品はこのレールから除外（「今集められる」=まだの物）。ただし全取得時は「全部集めました」の静かな祝辞＋/foodsへの導線に切り替え
- **価格**: 「価格未確認」の商品はこのレールに出さない（世界観を壊す文言をホームから排除。一覧/foodsでは従来通り表示）
- **スマホ可視範囲**: FV直下でカード全体（写真＋テキスト）が1スクロール以内に完全表示されること

## 10. Limited Collection Section（期間限定コレクション）

**結論: 25th固定をやめ、「期間限定コレクション」枠に汎用化する。**

理由: is25thFood()（home-progress-client.tsx 186〜206行）は25th専用の正規表現ヒューリスティックで、イベントが変わるたびにコード修正が必要。非コーダーが運用できない構造は弱い（指摘の通り）。

設計:

- **セクション名**: 「期間限定コレクション」。サブタイトルに現在のコレクション名（例「25thアニバーサリー」）を表示
- **表示ロジック（既存データで成立するか）**: Food型には eventName / collaborationName / seasonalVersion / isLimited / salePeriodLabel が存在する（types/domain.ts）。第一候補は「activeかつeventName（またはcollaborationName）が同一の商品グループのうち、件数が最多のもの」を自動選出する方式。**ただし eventName系フィールドの実データ充足率は本分析では未確認**。Codex実装前に充足率の確認が必要（後述の質問1）
- **フォールバック階層**: (1) イベントグループ自動選出 → (2) 充足率が低い場合は「isLimited && active」全体を『期間限定』コレクションとして表示 → (3) それも空なら本セクション自体を非表示（現行と同じnullリターン思想）
- **管理画面なしの運用**: 完全自動選出を基本とし、補助として lib/constants.ts に「注目コレクション設定」（タイトル＋抽出キーワード1組）を定数化する案を採る。イベント交代時は定数1箇所の書き換えで済み、Codexへの依頼が「定数を○○に変えて」の1行で完結する。将来 /admin に設定UIを作る拡張余地を注記として残す
- **コンプ欲の演出**: セクション見出し横に「あと◯品」を表示（このグループ内の未取得数）。小さい母数のコンプ単位を見せることが本セクションの最重要機能。グループ全取得時はゴールドの「コンプリート」スタンプ表示（このスタンプは棚のスタンプと同じ意匠系で統一）
- **取得状態の可視化**: レール内の取得済みタイルにも棚と同じ彩色＋スタンプ規則を適用（文字「食べた/残り」での区別は廃止）
- **25th監査資産の保護**: real-user-audit-v3で人手監査済みの25th判定結果は、キーワード定数の初期値として引き継ぐ（判定が後退しないこと）

## 11. Mobile Layout（390px / 430px）

下部ナビ（fixed、約64px＋safe-area）との共存を前提に、390px・ビューポート高約660〜750pxで設計。

**1画面目（スクロール0）で見えるもの**:

| 要素 | 高さ目安 |
|---|---|
| 上余白 | 16px |
| ロゴタイプ＋飾り罫＋タグライン | 約72px |
| 棚（2段×5列、タイル約68px角＋ギャップ） | 約146px |
| 銘板（コレクション数行＋ゲージ＋ラベル） | 約76px |
| セクション間余白 | 32px |
| 「今集められるフード」見出し | 約44px |
| 大判カード写真の上半分（チラ見せ） | 残り約120px〜 |

FV合計（ロゴ〜銘板）は約310〜330pxに収め、**1画面目で必ず「棚＋数字＋次のフード写真の頭」まで見える**こと。現行Hero（約420px）より約100px軽くする。

**2画面目以降の順序**: 今集められるフード（レール全体約330px）→ 期間限定コレクション（見出し＋あと◯品＋レール、約300px）→ エリア一覧（現行ポスターカード230px×10、維持）→ 最近の記録（記録がある場合のみ、写真3枚ストリップ約180px）→ 店舗から探す／全商品を見る／情報提供（現行のテキスト行型を維持、各約80px）。

規則: 横スクロールは「今集められるフード」「期間限定」「最近の記録」の3レールのみ。縦リズムはセクション間32〜48px。本文化粧テキストは各セクション1行まで。ページ全体でoverflow-x禁止（390px/430pxで横スクロール0）。下端は現行pb-32相当を維持し最終セクションがナビに隠れないこと。

430pxでは棚タイルが約76px角に拡大、その他は同構成。

## 12. Desktop Layout（1280px / 1920px）

スマホの引き伸ばしに見せないため、FVのみ2カラム化する。

- **1280px**: コンテンツ最大幅1080px（現行踏襲）。FVは左右分割 — 左カラム（約38%）: ロゴタイプ＋タグライン＋銘板（コレクション数・ゲージ）。右カラム（約62%）: 棚を3段×6列に拡張（タイル約88px角）。視線は「左で自分の数字、右で集めたものの顔」と流れる
- 今集められるフード: レールではなく**6カラムグリッド1段**（現行グリッドの列数活用）。ホバーで写真が1.03倍（現行トランジション踏襲）
- 期間限定コレクション: 横レール維持（PCでもスワイプ可、矢印は付けない — 現行思想踏襲）
- エリア: 現行2カラムポスター維持
- **1920px**: コンテンツ幅は1080pxのまま中央寄せ（広げない）。背景の紙色が左右に広がるだけにし、要素を拡大しない。棚タイルの最大サイズは96px角でキャップ
- 768px（タブレット）: モバイル構成のまま棚を2段×8列に拡張。FV2カラム化は1024px以上から

## 13. Do / Don't

**Do**:

- 棚＝実写真で進捗を見せる（取得=彩色＋金スタンプ、未取得=暖色トーンダウン）
- コレクション数（絶対値）を唯一の大きい数字にする
- 「販売中◯品（登録分）」「登録済みコレクション」という非断定の語彙を使う
- 日替わりシードで表示順を変え、再訪の差分を作る
- 「あと◯日」「あと◯品」で限定の鼓動と小さなコンプ単位を見せる
- 取得瞬間のみ短く上質なアニメ（reduced-motion対応必須）
- 背景はウォームの紙色、装飾は二層刻印ロゴと細いゴールド罫のみ
- エリアポスターカード・カード規律（バッジ最大2等）・下部ナビは現行維持

**Don't（禁止）**:

- ロックアイコン・?マーク・シルエット黒塗りでの未取得表現
- 「5品達成まであと4品」型のカウントダウンチュートリアル
- 複数商品の合成写真バナー・LP風メインビジュアル
- ドット・グリッド・放射グラデ等のAIテンプレ風背景（現行の光スイープ・円形ボーダーは削除）
- SaaS風白カード枠・管理画面風サマリー・統計カードの並列
- ただの巨大数字（%単独の3.75rem表示は廃止）・ただの太字「ユニコレ」
- 「全183品」「全フード」「完全収録」等データ完全性の断定
- アイコン追加・ヘッダー追加・英語装飾タグ（COLLECTION等）・絵文字アイコン
- 紙吹雪・虹色・レアリティ演出・ポップアップ等ソシャゲ的祝祭
- 常時ループする装飾アニメ
- 集計ロジック（calculateCompletion等）の定義変更・ユーザーデータschema変更
