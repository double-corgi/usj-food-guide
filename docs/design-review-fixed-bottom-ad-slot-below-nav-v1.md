## 重点確認（実コードによる検証）

### 下部ナビとの干渉 → 機能的には回避できている
- **z-index**: 広告 `z-40` < ナビ `z-50`（`app-header.tsx` 確認）。ナビが常に前面でタップ領域は遮られない。✅
- **pointer-events-none**: 広告はタップを捕捉しない。重なってもタップは透過。✅
- → モバイルのナビ操作性は阻害されない。

### モバイル幾何（safe-area 下端基準）→ 視覚的に問題
- ナビ: bottom `+0.75rem`、高さ約3.5rem → 占有 **約0.75–4.25rem**、不透明白、inset-x-4。
- 広告: bottom `+0.125rem`、`h-5`=1.25rem → 占有 **約0.125–1.375rem**、z-40、inset-x-10・max-w-[10rem]（中央、ナビ横幅の内側）。
- 重なり: 0.75–1.375rem。**広告の可視部は 0.125–0.75rem の約0.625rem（≈10px）スリットのみ**。残り（≈10px、中央寄せ「広告」ラベルを含む帯）は不透明ナビの背後に隠れる。
- → 「ナビの下に移動」は座標上は達成。しかし**フローティングナビ直下には実質0.75remの隙間しかなく、20pxのピルが収まらず大半が隠れる**。`広告`表記も境界でクリップされうる。

### safe-area
- モバイル/デスクトップとも `calc(env(safe-area-inset-bottom)+…)` を使用。✅

### z-index 全体像
- ナビ z-50 / 広告 z-40 / pwa-register z-40 / ヘッダー(sticky,PC) z-30。広告とナビの上下関係は適切。デスクトップでは広告(下中央)と pwa-register(md:bottom-6,右)が同じ z-40 だが配置が左右で分離しており通常は非干渉。✅（軽微留意）

### デスクトップ
- 下部ナビは `md:hidden`。広告は bottom `+1rem`・中央・`h-9`・cream半透明の小ピル。常時フロート表示だが小型で控えめ。✅（「過剰に目立たない」）

### 本番広告コード
- script/iframe/SDK/AdSense/外部通信なし。`pointer-events-none` の静的プレースホルダー。✅

## 条件（条件付き承認の理由と修正方針）

機能的なナビ非干渉は達成済みで、本commitの差し戻しは不要。ただし**Phase 2 / 実広告化に進む前に、モバイルの固定広告方針を見直すこと**を条件とする。

**問題:** モバイルのフローティング下部ナビの「直下」には実質 ~0.75rem の隙間しかなく、固定広告ピル(20px)の大半がナビ背後に隠れる。可視部は約10pxのスリットのみで、「広告」ラベルも境界でクリップされる。これは「ナビを壊さない」が「広告自体が壊れて見える」状態であり、実広告（高さのあるバナー）はこの位置に成立しない。これは元設計 `docs/unicole-ad-slot-design-v1.md` が「常時下固定広告＝NO（フローティングナビと構造干渉）」と結論した点と一致する。

**推奨修正（いずれか）:**
1. **（推奨）モバイルはインライン方式へ戻す**: 元設計どおり `/foods` 等のコンテンツ末尾にインライン広告（`variant="inline"`）。固定広告は**デスクトップ限定**（モバイルは `hidden md:block`、または fixed variant をデスクトップのみ描画）。デスクトップは下部ナビが無いため下中央固定が自然に成立する。
2. もし固定広告をモバイルでも出すなら、**ナビの「上」に十分な高さで配置**し、`main` の `pb` をナビ＋広告分だけ確保する（旧 +5.25rem 系の発想）。ただしこれは画面下を二重占有し UX を圧迫するため非推奨。
3. 暫定でこのまま出す場合でも、最低限 **モバイルで「広告」ラベルがナビ背後にクリップされない高さ・位置**にするか、モバイルでは fixed 広告を非表示にする。

> いずれも本レビューの対象外ファイル（app/foods/page.tsx 等）に波及しうるため、方針確定後に別 /goal とする。本commit自体は安全なので巻き戻し不要。

## 補足（非ブロッキング）

1. **設計方針からの転換の記録**: 元設計は「固定広告 NO・インライン推奨」。本系列(d65bc11〜)で固定広告へ転換し foods インラインを撤去している。方針転換自体は進行側判断だが、上記モバイル制約により**元設計の懸念が実機で顕在化**した形。
2. **デスクトップ単体では妥当**: 下部ナビが無いデスクトップでは、下中央の小型固定ピルは自然で控えめ。固定広告を活かすならデスクトップ限定が筋。
3. **`pb-32` の妥当性**: 広告がナビ背後に移りスタック高が減ったため、`pb-44→pb-32`(モバイル)でも本文・フッターはナビ(~4.25rem)を十分にクリアする。妥当。

## 結論

スコープ・安全性（ナビのタップ非干渉、safe-area、クリック不可、本番広告コードなし、Coverage 不変）は満たしており、本commitの巻き戻しは不要。一方で、フローティング下部ナビ直下という配置はモバイルで広告（および「広告」ラベル）の大半がナビ背後に隠れる視覚的破綻を生み、実広告化の土台にならない。よって **条件付き承認**：Phase 2／実広告化の前に、モバイルはインライン方式へ戻す（固定はデスクトップ限定）等の方針見直しを行うこと。
