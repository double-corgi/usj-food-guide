レビュー担当: Claude（プロダクト責任者 / UX / UIデザイナー）
対象: Codexによる docs/codex-goal-home-v1.2.md の実装
確認方法: iOS Simulatorスクリーンショット（home-design-v1-2-ios-simulator-390 / -430.png）とブラウザスクリーンショット（-390/-430/-768/-1280/-1920.png）の目視、変更ファイルの差分確認（globals.css / home-progress-client.tsx のみ変更、layout.tsx / app-header.tsx / home-dashboard.tsx は未変更をタイムスタンプで確認）。

## 1. 総合判定: **条件付き承認**

v1.2の主目的である **ホームのDynamic Island干渉（P0）は解消をSimulatorスクリーンショットで確証した**。0品文言・重複文言のP2も両方解消。v1.1の見た目は無傷で、変更はホームに閉じている（layout.tsx不変）。

条件として残るのは1点: **ホーム以外の6ページの上部safe-area安全性が未確証**であること。指示書1-2は「Simulatorで他ページの上部を目視確認し報告」を求めたが、他ページのSimulatorスクリーンショットも最終報告書も提出されていない。コード上、他ページのモバイル上余白は `layout.tsx` の `pt-6`（24px）のみで safe-area 処理が無く、iPhone 14 Pro系（セーフエリア約59px）ではページ見出しが島に近接・潜在的に被る構造が残っている。アプリ（Capacitor）公開前にこの確認または最小修正が必要。

## 3. 実装内容の確認（コード）

- 変更は `app/globals.css`（`.home-collection-hero` クラス追加）と `components/home-progress-client.tsx`（クラス適用・0品文言変更）の2ファイルのみ。**スコープ遵守は完璧**
- safe-area実装: モバイルは `padding-top: max(env(safe-area-inset-top), 1rem)`、640px以上は1.25rem、1024px以上は2rem。env非対応環境でもmax()のフォールバックで破綻しない
- `app/layout.tsx` / `app-header.tsx` は未変更（指示書の「ホームだけで解決できるならホームだけでよい」に沿った判断として妥当）

## 4. 問題分類

### P1: 他ページのsafe-area未確証（条件付き承認の条件）

`/foods` `/foods/[id]` `/eaten` `/areas` `/stores` `/stores/[id]` はモバイルで上部セーフエリア処理が無いまま。ブラウザ・PWA(Safari表示)では問題ないが、Capacitor/standaloneでは見出しが島に近接〜被る可能性が高い（ホームと同じ構造的原因）。対応はどちらかを選ぶ:

1. iPhone 14 Pro系Simulatorで6ページのスクリーンショットを取得し「安全」を確証する（被っていなければ追加実装不要）
2. 被っている場合は、`app/layout.tsx` の main にモバイル限定の `padding-top: max(env(safe-area-inset-top), 1.5rem)` 相当を入れる最小修正（その場合は全7ページ×全幅の確認必須。ホーム側と二重加算にならないよう調整が必要な点に注意）

### P2: Codexの最終報告書が未提出

lint / typecheck / build の結果、commit hash（backup / fix）、push、Vercel反映が報告されていない。v1.1のときも未提出のままであり、指示書の報告テンプレートが2回連続で守られていない。成果物は画面で確認できているが、ビルド成否とデプロイ状態はレビューで代替できないため提出を求める。

### P3

1. **640〜767pxの帯域でsafe-area処理が消える**: `.home-collection-hero` は640px以上で固定1.25remになる。iPadや横向き大型端末をCapacitorで使う場合、この帯域だけenv()が効かない。768px以上はPCヘッダー（safe-area処理あり）が出るため実害は限定的だが、640px以上も `max(env(safe-area-inset-top), 1.25rem)` にしておく方が堅牢
2. Simulatorスクリーンショットに Next.js dev インジケータ（「11 Issues」バッジ）が写り込んでいる。本番ビルドでは消えるため指摘のみ。ただし将来のストア提出用スクリーンショットには本番ビルドを使うこと

## 5. 結論

v1.2のスコープ（ホームP0＋P2×2）は完遂され、ホームはブラウザ・iOSアプリ両方で初めて「切れない・くすまない・重複しない」状態になった。ホーム単体としては承認できる品質。

条件は「**他6ページのsafe-area確証（Simulatorスクリーンショット提出）または最小修正**」と「**v1.1/v1.2の最終報告書（ビルド結果・commit・Vercel）の提出**」。両方が揃えば全体承認に切り替える。確認の結果、他ページに被りがあれば、その1点だけのv1.3（layout最小修正）を発行する。

なお修正版 /goal はまだ作成しない（オーナーの指示待ち）。
