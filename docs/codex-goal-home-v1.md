## 1. Objective

ホーム（`/`）を「整理された進捗ページ」から「集めたくなるコレクション体験」に変える。

達成基準:

- 開いた瞬間、フード写真の棚（コレクション棚）が見え、自分の取得状況が「色」で分かる
- 数字の主役は「コレクション数（食べた数の絶対値）」1つだけ。巨大%表示は廃止
- 「今集められるフード」が大判写真で食欲を作る
- 25thハードコードを「期間限定コレクション」に汎用化する
- データ完全性を断定する文言（「全183品」等）が画面から消える
- ホーム以外のページの表示・集計数値は一切変わらない

## 2. 現在の問題（要約）

- ファーストビューが「太字ロゴ＋説明文＋ 0/183 ＋ 0%」の成績表で、フード写真が1枚も無い
- 進捗が数字とバーだけで、集めた実感・欲しい感情に接続していない
- 光スイープ・放射グラデ・円形ボーダーが汎用装飾で AI テンプレ感を出している
- 25th コレクションが `is25thFood()` 正規表現ハードコードで、イベント交代のたびにコード修正が必要
- 「183品」が「全フード数」と誤解される表現になっている（実際は公開品質フィルタ通過済み・販売中・canonical統合後の登録数）
- `home-dashboard.tsx` が `<main>` を描画し、`app/layout.tsx` の `<main>` と入れ子になっている（セマンティクス不正・余白二重）

## 3. 実装対象（スコープ）

やること:

1. ファーストビュー刷新（ロゴタイプ刻印化＋コレクション棚＋銘板）
2. 「今集められるフード」を大判横スワイプレール化＋日替わりローテーション
3. 「25thアニバーサリー」を「期間限定コレクション」に汎用化
4. 「最近の記録」ストリップ新設（記録がある場合のみ）
5. セクション順序の再編、`<main>` 入れ子の解消、光スイープ等の装飾削除
6. 取得瞬間のスタンプ演出（控えめ・1回限り）

やらないこと（スコープ外）:

- `/foods` `/eaten` `/areas` `/stores` 等、ホーム以外のページの改修
- 「次回食べたい」機能の変更（オーナー決定: 機能は残す。ただし**ホームのファーストビューには出さない**。商品詳細・食べたページ・探すページ側の補助導線のままにする。今回は一切触らない）
- 集計ロジック・データ取得・管理画面・crawler の変更

## 6. UI仕様 — ファーストビュー

構成（上から順）:

**(1) ブランド行**

- ユニコレのロゴタイプ（7章仕様）＋タグライン「食べた記録が、そのままコレクションになる。」を1行・小さく（13px前後・slate系）
- 現行の説明文2行（「ユニバ（USJ）フードを写真で集めて…」）は削除
- アイコン追加禁止・ヘッダー追加禁止

**(2) コレクション棚（FVの主役）**

- 実フード写真の正方形タイルをモバイル2段×5列で敷く（9〜10章仕様）
- 取得済み: フルカラー＋右下に直径16px程度のゴールドスタンプ（円形、チェック刻印風。Gold `#fdbb30` 基調＋Navy）
- 未取得: 暖色トーンダウン（彩度低下＋わずかな暖色フィルタ。**グレースケール禁止・黒塗り禁止・ぼかし禁止**）
- 各タイルは該当商品の `/foods/[id]` へのリンク
- タイル角丸8〜10px、ギャップ4〜6px、枠線・影なし

**(3) 銘板（数字行）**

- 1行目: 「コレクション {eaten}」— 数字のみ32〜40px・font-black・Navy(`ink`)。**画面内で大きい数字はこれ1つだけ**
- 同行に従属表示: 「/ 販売中 {total}品（登録分）・残り {remaining}」— 12〜13px・slate
- 直下: 高さ4pxの進捗ゲージ（既存の Blue→Gold グラデ。グロー影 `shadow-[0_0_22px...]` は削除。0%でも土台表示）
- ゲージ右端に小さく達成率%（11〜12px）。**巨大%（現行3.75rem）は廃止**

**(4) 背景**

- 放射グラデ・円形ボーダー・`animate-home-light-sweep` を全削除
- セクション背景はごく薄いウォーム紙色（`#fffaf5` 系）を白との微差で敷く。グラデ装飾は置かない

**(5) チラ見せ**

- 390pxの1画面目で「ロゴ＋棚＋銘板＋『今集められるフード』見出し＋1枚目写真の上端」が見える高さ配分にする（FV全体をロゴ〜銘板で約310〜330pxに収める）

## 7. ユニコレロゴ仕様

- テキストのみ。アイコン・画像・SVGロゴの追加禁止
- **二層刻印**: Navy(`#071b3a`)の「ユニコレ」の背面に、同じ文字を Gold(`#fdbb30`) で右下1pxオフセットして重ねる（箔の版ずれ風。CSSの擬似要素または重ね描画で実現）。現行の `home-unicole-logo` の text-shadow はこの明示的二層に置き換える
- **飾り罫**: 現行の下線3pxを廃止。ロゴの左右に、文字の垂直中央へ細いゴールド水平罫（高さ1px・長さ16〜24px）を置き「— ユニコレ —」の銘板構図にする
- サイズ: モバイル28〜30px / PC 32〜36px。字間 +0.04em 程度
- 20px以下に縮小される文脈では二層をやめ単層Navyにフォールバック
- グラデ文字・縁取り・斜体・英語サブタイトル禁止

## 8. データ仕様

- 商品データは既存の `listFoods()`（props 経由）と `useFoodLogs()` のみを使う。新規 fetch・新規 API・新規テーブル禁止
- 取得判定は既存の `getEatenCanonicalKeys` / `getCanonicalFoodKey` / `isEatenCanonical` を使用（canonical 単位）
- コレクション数・total・残りは既存 `calculateCompletion(foods, logs)` の戻り値をそのまま表示する。**値の計算方法を一切変えない**（改修前後で数値が一致すること）
- 画像は `FoodImage` コンポーネント経由（= `sanitizePublicFood` 通過済みの公開画像のみ）。**それ以外の画像ソースを参照しない**（オーナー決定 3）
- 「価格未確認」「エリア確認中」「カテゴリ確認中」等の未確認系文言を、ホームの新セクションに**表示しない**（該当商品は価格非表示にするのではなく、レール選定から除外する。6章の棚タイルには写真のみなので影響なし）
- **日替わりシード**: 「今集められるフード」の表示順に、日付（Asia/Tokyo、YYYY-MM-DD）を seed にした決定的シャッフルを加える。`Math.random` 直接使用禁止（SSR/CSR間のhydration不一致と revalidate 3600 との不整合を避けるため、同一日付なら同一順序になる純関数にする）
- 文言規則: 「全◯品」「全フード」「完全収録」「コンプリート図鑑」を**画面のどこにも出さない**。母数は「販売中 {total}品（登録分）」、総称は「登録済みコレクション」を使う

## 9. コレクション棚仕様

- タイル数: モバイル 2段×5列=10。タブレット(768px) 2段×8列=16。PC(1024px以上) 3段×6列=18
- タイル選定ロジック:
  1. 取得済み商品（eatenCanonicalKeys に含まれる）を新しい記録順に先頭へ（最大で枠の半分まで）
  2. 残り枠は未取得の販売中商品から「画像あり必須・isLimited優先・日替わりシード」で充填
  3. 0品ユーザー: 全タイルが未取得（淡トーン）で埋まる。空白・プレースホルダSVGのタイルを作らない（画像のある商品だけ使う）
- 取得済みタイル: フルカラー＋ゴールドスタンプ（右下、16px円形）
- 未取得タイル: CSSフィルタで彩度約50〜60%・明度やや上げ・暖色寄せ（例: sepia系を弱くかける）。**ロック・?・黒塗り・ぼかし禁止**
- 「食べた」登録直後（同一セッション内）: 該当タイルが彩色されスタンプが押される 400〜600ms のアニメ（既存 `achievement-unlock` キーフレーム転用可）。1回限り・ループ禁止。`prefers-reduced-motion` 時は即時切替
- 棚の下に銘板（6章(3)）を一体配置。棚と銘板を白カードで囲まない（背景に直置き）

## 10. 未取得商品の見せ方（全セクション共通規則）

- 未取得は「まだ味わっていないごちそう」として実写真で見せる（オーナー決定 3: sanitizePublicFood 通過画像のみ）
- 表現は暖色トーンダウンのみ
- **禁止**: ロックアイコン / ?マーク / 黒塗りシルエット / グレースケール / ぼかし / 「未開放」等のゲーム文言
- 期間限定コレクションのレール内も同一規則（取得済み=彩色＋スタンプ、未取得=淡トーン。現行の「食べた / 残り」テキスト区別は廃止）

## 11. 期間限定コレクション仕様（25th汎用化）

オーナー決定 1 を実装する:

- セクション名は「期間限定コレクション」。サブタイトルに現在のコレクション名を表示
- **選出の優先順位**:
  1. `eventName` または `collaborationName` が同一の active 商品グループのうち件数最多のものを自動選出（タイトルはそのフィールド値）
  2. 充足率が低くグループが成立しない場合（active 3品未満を目安）: `lib/constants.ts` の注目コレクション定数（タイトル＋キーワード。初期値は25th: real-user-audit-v3 で人手監査済みの `25th|25周年` 系キーワードを引き継ぎ、`5th-anniversary` 除外条件も維持）でキーワードマッチ
  3. それも成立しない場合: `isLimited && active` 商品全体を「期間限定」コレクションとして表示（`salePeriodLabel` があれば補助表示）
  4. それも空: セクション自体を非表示（null リターン）
- 実装前に `scripts/output/foods.generated.json` の `eventName` / `collaborationName` 充足率を確認し、どの段が実際に動くかを最終報告に記載すること
- `is25thFood()` への依存を撤去（関数削除可。ただしキーワード初期値として監査結果を `lib/constants.ts` に移管してから消すこと。判定品質を後退させない）
- セクション見出し横に「あと {グループ内未取得数}品」を表示（小さいコンプ単位の提示が本セクションの最重要機能）
- グループ全取得時: ゴールドの「コンプリート」スタンプ表示（棚のスタンプと同一意匠系。紙吹雪等は禁止）
- 運用要件: イベント交代は `lib/constants.ts` の定数1箇所の変更だけで完結すること（管理画面は作らない）

## 12. 今集められるフード仕様

- モバイル: 横スワイプの大判カードレール。カード幅は画面幅の約72〜78%（390pxで280〜300px）、次カードが約20%見える。写真比率4:3（高さ約210px）
- 件数: 8件＋レール末尾に「すべて見る → /foods」カード
- 選定: 販売中・未取得・**画像あり必須**・**価格確認済みのみ**。優先順: 終了間近（`getRemainingDays` 少ない順）→ `isLimited` → 既存 `scoreHomeFood` 系スコア → 日替わりシード
- カード情報（写真下3行以内): 商品名（15px・font-bold・2行固定）/ 価格（太字）＋エリア名（小・slate）/ 状態チップ最大1個（「あと◯日」=berry または「限定」）。**写真上にバッジを載せない**
- 取得済み商品は除外。全品取得時は静かな祝辞テキスト＋ /foods 導線に切替
- PC(1024px以上): レールではなく6カラムグリッド1段（8件中6件＋すべて見る導線は見出し右の既存パターン）

## 13. モバイル仕様（390px / 430px）

- セクション順: ①FV（ロゴ＋棚＋銘板）②今集められるフード ③期間限定コレクション ④エリア一覧（現行維持）⑤最近の記録（記録がある場合のみ、横スクロール写真3枚＋「アルバムを見る → /eaten」）⑥店舗から探す ⑦全商品を見る ⑧情報提供（現行のテキスト行型を維持）
- 1画面目（スクロール0・390px）: ロゴ行（約72px）＋棚2段（約146px）＋銘板（約76px）＋余白＋「今集められるフード」見出しと1枚目写真上端が見えること
- 横スクロールはレール3つ（今集められる/期間限定/最近の記録）のみ。ページ全体の横overflow禁止
- 下部ナビ: 現行 `pb-32` 相当のクリアランス維持。最終セクションがナビに隠れないこと
- 説明的テキストは各セクション1行まで
- 430px: 棚タイルが約76px角に拡大、構成同一

## 14. PC仕様（768px / 1280px / 1920px）

- 768px: モバイル構成のまま棚を2段×8列に
- 1024px以上〜1280px: コンテンツ最大幅1080px維持。FVのみ2カラム — 左（約38%）にロゴ＋タグライン＋銘板、右（約62%）に棚3段×6列（タイル約88px角）。今集められるフードは6カラムグリッド

- ホバー: 写真1.03倍の既存トランジション踏襲。新規のホバー演出は追加しない
