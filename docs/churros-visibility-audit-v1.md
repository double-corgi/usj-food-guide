## 1. チュリトス表示漏れの原因整理

可視判定は `lib/repositories/foods.ts#isVisibleFood`（全条件AND）:
`reviewStatus===approved` ∧ `canonicalFood!==false` ∧ `!hidden` ∧ `displayQuality!==low` ∧ `status!==inactive` ∧ `nameQualityScore>=60` ∧ `confidenceScore>=45` ∧ `!compositeMenu` ∧ `sourceUrl` ∧ 店舗/公式画像条件。

churro 61件 → 可視 **13** / 抑制 **48**。抑制48の内訳:

| 抑制理由カテゴリ | 件数 | 性質 | 復帰可否 |
|---|---|---|---|
| **販売終了（sale=ended）** | **30** | 期間限定コラボの終売（鬼滅/呪術/コナン/ワンピ/サンリオ/クリスマス/ハロウィン等） | ❌ 出さない（終売） |
| **販売中だが画像0枚＋pending＋dq=low** | **9** | 現行コラボ churros だが**画像が1枚も無い**・未レビュー | ⛔ 画像なしのため出せない（要・手動画像＋検証） |
| **可視 churro の重複（canon=false/hidden）** | **約9** | 既に表示中の churro と同一（キャラメルポップコーン/虚式茈/ウィキッド/ハローキティ/ミニオンチョコバナナ/チョコレート 等の重複） | ❌ 出すと二重表示 |

> 画像を持つ抑制 churro は **2件のみ**（food-14zoddb, food-1v2f6xx）で、いずれも**可視 churro の重複**（キャラメルポップコーン / ハローキティ）。復帰させると重複になる。

**結論**: 「カテゴリ漏れ」の正体は (a) 終売、(b) 画像なし現行コラボ、(c) 重複。**カテゴリ誤分類ではない**（churros は category=churro に正しく入っている）。

## 7. 安全な修正方針

- **override 層では churro を可視化できない**: `data/duplicate-overrides.json`＋apply は canonical/hidden 統合専用。displayQuality=low・reviewStatus=pending・canon=false を覆して visible にする機能は無い。
- **generated JSON 直接編集は禁止**、crawler/DB/translations/外部画像取得も禁止 → **今回、自動でできる安全な churro 可視化は無い**。
- **正しい安全経路（将来・人手前提）**:
  1. 3-B の現行品について、公式画像を**人手で確認・取得**し `public/manual-images/<id>/` に保存（確証あるもののみ）。
  2. 当該 id を可視化するための**「可視化オーバーライド層」**（duplicate-overrides と同型の宣言ファイル＋apply）を新設する設計が別途必要（displayQuality/reviewStatus/canonical を id 単位で安全に上書き、全件差分ガード付き）。
  3. 1件ずつレビュー→承認→反映。
- これらは**確証（画像・販売状況）が前提**で、今回の「最小修正」スコープには載せない。
